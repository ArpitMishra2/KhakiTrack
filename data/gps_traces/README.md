# GPS run analysis and test traces

Every GPS run is analysed twice with the same rules: on the phone (`app/lib/gps/run_analysis.dart`) for instant feedback, and on the server (`supabase/functions/submit-run/analysis.ts`), whose verdict is the one that counts for leaderboards. Both are tested against the traces in this folder, so the two implementations cannot drift apart silently.

## Trace format

```json
{
  "description": "...",
  "target_m": 4800,
  "points": [{"t": 0, "lat": 26.15, "lon": 80.17, "acc": 6.0, "mock": false}],
  "expected": {
    "verdict": "verified",
    "flags": [],
    "distance_m": [4700, 4950],
    "finish_seconds": [1480, 1530]
  }
}
```

`t` is milliseconds since the run started. `expected.distance_m` and `expected.finish_seconds` are inclusive ranges, or null.

Traces are synthetic, generated by `generate.py` (fixed random seed, so the output is reproducible) around a 400 m loop near Ghatampur. GPS error is modelled as slowly drifting (AR(1), 3 m) plus a little independent jitter, which is closer to how phone GPS behaves than independent noise per fix. Real traces recorded on Arpit's phone should be added here as they become available, with the expected result checked by hand.

## Rules (version 1)

Thresholds are in `RULES` at the top of both implementations and must stay identical.

1. **Clean-up.** Sort by time, drop points with the same timestamp as the previous one.
2. **Mock locations.** Any point flagged as mocked: `mock_location` (reject).
3. **Accuracy.** Drop points with accuracy worse than 30 m. If more than 30% are dropped: `poor_signal` (suspicious).
4. **Teleport.** On the accurate raw points: a step longer than 50 m at more than 12 m/s is `teleport` (reject). Its distance is not counted.
5. **Smoothing and jitter.** Distance is measured on a smoothed track: each point is replaced by the average of itself and the same number of points on each side (up to 2), using only neighbours within 10 s and never across a gap or teleport, so the ends of the run are not biased. Then a point closer than 2 m to the last kept point is skipped, so standing still does not add distance. Without smoothing, independent GPS noise of a few metres per fix can nearly double the measured distance of a run.
6. **Signal gap.** A step longer than 20 s is a gap. It is `signal_gap` (suspicious) if it lasts more than 45 s or covers more than 200 m in a straight line (the real path is unknown and on a loop can be much longer), or if gaps add up to more than 15% of the run time.
7. **Impossible speed.** Any 30 s window averaging more than 9 m/s: `impossible_speed` (reject).
8. **Vehicle.** Any 180 s window averaging more than 6 m/s (faster than 2:47 per km for three minutes): `vehicle_like` (reject).
9. **Average.** Over 1500 m or more, an average above 6.2 m/s: `implausible_average` (reject).
10. **Sampling.** Fewer than one kept point per 10 s on average: `sparse_samples` (suspicious).
11. **Too short.** Under 60 s or under 200 m: `too_short` (suspicious; not eligible for rankings).
12. **Finish time.** The first moment the cumulative distance reaches `target_m`, interpolated linearly inside the step that crosses it. Null if never reached.

Verdict: `rejected` if any reject flag, otherwise `suspicious` if any suspicious flag, otherwise `verified`.

Why these numbers: the 5000 m world record is 12:35 (6.6 m/s average); top Indian club runners are around 14 minutes (6 m/s). PET candidates qualify at 3.2 m/s (UP Police, 4.8 km in 25 min) or 3.5 m/s (SSC GD, 5 km in 24 min). A sprint of 7.5 m/s over 200 m is possible and must not be flagged; 9 m/s for 30 s or 6 m/s for 3 minutes is not a candidate on foot.
